# infinite-english

무한 계단 스타일 3D 영어 어휘 학습 게임 (초3~중3).
정답을 맞히면 계단 구간이 열리고, 좌/우 탭으로 올라간다.

- 기획: [`prd.txt`](prd.txt)
- 작업 계획: [`docs/영어계단-작업계획.md`](docs/영어계단-작업계획.md)
- 배포: **Cloudflare Workers Static Assets** (`wrangler.jsonc`, `~/WorkSpace/elementary-math-warrior`와 동일 환경)
- 렌더링: three.js + glTF

## 현재 상태

**Phase 7 — 보스·랜덤 이벤트 완료.** 한 판에 기승전결이 생겼다 — 계단을 오르다 보스를 만나
약점 단어로 싸우고, 중간중간 이벤트가 규칙을 잠깐 바꾼다.

**단어 DB 1,000개 완료** (Level 1~10, 초3~중3).

**계단 규칙 개편.** **문제는 보스전에서만 나온다** — 계단은 항상 열려 있고, 10층마다
보스가 길을 막는다. 방향을 틀리거나 계단 타이머가 0 이 되면 판이 끝난다.
PRD 의 "정답 → 계단 개방" 구조와 3.2절을 뒤집은 결정이다(위험은 아래에 적었다).

남은 것: **보급형 태블릿 실기기 30fps 실측**, 태블릿 가로 2단 레이아웃,
D1 연결(현재 `/api` 503), Phase 9(밸런싱 — 시뮬 정답률 62~75% vs 목표 75~85%).

```bash
npm install
npm run dev        # → http://localhost:5173                    게임
                   #   http://localhost:5173/quality.html        단어 품질 검수 (Phase 3)
                   #   http://localhost:5173/spikes/spike.html   스파이크 A/B 검증 페이지
npm run assets     # 3D 에셋 병합 → public/models/*.glb
npm run words      # 단어 시드(TSV) 검증 → src/data/words/level-N.json
npm test           # 퀴즈 품질 · 학습 엔진 · 성장 · 저장 · 보스·이벤트 · 계단 · 배치 · 레벨 선택 · 상점 (200항목)
npm run typecheck
npm run build      # dist/ (index.html + quality.html + models + _headers)
npm run deploy     # 빌드 후 wrangler deploy
```

`npm run dev`는 `host: true`로 열리므로 같은 네트워크의 실제 모바일·태블릿에서 접속해 확인할 수 있다.

### 게임 루프

```
계단을 자유롭게 오름 (계단 타이머만 압박) ──→ 10층마다 보스가 길을 막는다
   ▲                                              │
   │                                       문제는 **여기서만** 나온다
   └── 처치 ←── 정답 = 보스 HP 감소 ←────────────┘
                오답 = HP-1 → HP 0 이면 REVIVE

판이 끝나는 세 가지 — ① 영어 오답으로 HP 0 + REVIVE 실패
                    ② **방향 오선택** (즉시)
                    ③ **계단 타이머 0** (즉시)
```

**"정답 → 계단 구간 개방" 구조를 없앴다.** 계단 몇 칸마다 문제가 끼어들어 오르는 집중이
끊긴다는 지적이었다. 이제 계단은 항상 열려 있고 영어는 **보스라는 관문**에서만 묻는다.
계단 구간의 긴장은 방향 선택과 계단 타이머가 담당한다.

콤보는 보스전 안에서 쌓이고 **피해량과 계단 색**을 올린다. 처치하면 콤보 단계만큼의 계단이
물든다(보상 연출 — 진행을 막지는 않는다).

| 콤보 | 물드는 칸 | 연출 |
|---|---|---|
| 1~2 | 4칸 | 일반 |
| 3~4 | 6칸 | 일반 |
| 5~9 | 8칸 | GOLD STEP (계단이 금색) |
| 10~19 | 10칸 | FIRE STEP |
| 20+ | 12칸 | ULTRA COMBO |

### 조작

계단이 좌/우로 꺾인다. **꺾이는 쪽을 눌러야** 한 칸 오른다.

- 화면 좌/우 절반 탭, 좌/우 스와이프, 키보드 `←` `→` (또는 `A` `D`)
- **방향을 틀리면 판이 끝난다.** 원작(무한의 계단)의 규칙이다
- 계단은 문제를 맞혀서 열린 구간에서만 오를 수 있다 — 영어를 맞혀야 게임이 진행된다

> **이 규칙은 PRD 3.2절을 뒤집은 것이다.** 원래 설계는 "조작 실수로 판이 끝나면 영어를 틀려서
> 실패했다는 인과가 무너진다"였고, 틀려도 0.4초 휘청이고 계속했다. 계단의 긴장이 방향 선택에서
> 온다는 요청으로 바꿨다. 인과 문제는 남아 있으므로 완화 장치를 둔다 —
> `?autodir=1`(방향 자동 보정)이면 방향으로 죽지 않고, 결과 화면이 종료 사유를 구분해 보여 준다
> ("방향을 틀렸어!" / "시간이 다 됐어!" / "아깝다!").

### 계단 · 갈래 길

계단 블록은 **KayKit Block Bits**(CC0)에서 온다. 테마마다 3종을 섞어 같은 구간에서도
블록이 달라 보인다 — 한 종류의 반복은 5,000층을 오르는 게임에서 가장 빨리 지친다.

| 테마 | 블록 | 가짜 계단 |
|---|---|---|
| 숲 | grass · dirt_with_grass · gravel_with_grass | `prototype` (회색 격자) |
| 성 | stone · bricks_A · stone_dark | `prototype` |
| 설산 | snow · grass_with_snow · dirt_with_snow | `striped_block_red` (빨간 줄무늬) |
| 하늘섬 | wood · metal · glass | `striped_block_red` |

블록은 **2×2×2** 로 만들어져 있어 실측 크기에서 배율을 계산해 1 유닛으로 정규화한다.
14종이 텍스처 1장(1024px·30KB)을 공유한다. 다만 단순 큐브가 아니라 **블록당 삼각형이
108~1296개**라 계단만으로 화면당 약 18k~29k 삼각형을 쓴다(예산 150k). `lava`(2076)는 제외했다.

#### 방향 패턴

매 칸을 독립 난수로 뽑으면 **어느 구간이나 똑같이 느껴진다** — 무작위는 리듬이 없다.
그래서 4~9칸씩 묶어 패턴을 하나 고른다:

| 패턴 | 리듬 |
|---|---|
| zigzag | 번갈아 — 손가락이 좌우로 |
| stair | 둘씩 같은 쪽 — 둘·둘로 끊긴다 |
| run | 같은 쪽으로 이어 간다 (`maxRun` 에서 꺾인다) |
| random | 예측 불가 |

구간이 바뀌는 순간에 리듬을 다시 잡아야 한다. `maxRun`(3)은 어느 패턴에서도 지킨다 —
같은 방향이 길게 이어지면 계단이 화면을 벗어나고 조작이 연타가 된다.

#### 가짜 계단

진짜 계단의 **반대쪽에 블록이 하나 더** 놓여 두 갈래로 보인다. 한쪽은 밟으면 판이 끝난다.

| | |
|---|---|
| 첫 등장 | 12층 — 조작과 규칙을 익힐 구간을 지나서 |
| 간격 | 최소 5칸 (연달아 나오면 운에 맡기는 게임이 된다) |
| 확률 | 간격 조건을 통과한 칸에서 30% |
| 보스 층 | **제외** — 관문과 함정이 겹치면 원인을 못 읽는다 |
| 판정 | **시드와 무관하게 층 번호로 결정** — 같은 층은 늘 같은 함정이어야 아이가 배운다 |

가짜 블록에는 **테마 색조를 곱하지 않는다.** 테마에 물들면 이질감이 사라져 함정이
불공정해진다. 종료 사유도 구분된다 — "가짜 계단이었어! / 생김새가 다른 블록은 밟으면 안 돼."

#### 기믹 군집

크리스탈이 앞 칸에 있으면 45% 확률로 이어져 **2~3개 군집**이 생긴다. 같은 확률로 흩어 놓으면
어느 구간이나 "가끔 하나"가 되어 리듬이 없다. 군집이 보이면 "여기서 벌 수 있다"가 읽힌다.

### 계단 타이머

한 칸에 머무를 수 있는 시간이다. **0 이 되면 판이 끝난다.** 한 칸을 밟을 때마다 다시 찬다.

`3.0초 × 0.88^(층/100)`, 하한 2.0초.

| 층 | 한 칸 대기 시간 |
|---|---|
| 0 | 3.00초 |
| 100 | 2.64초 |
| 200 | 2.32초 |
| 300 | 2.04초 |
| 320~ | **2.00초** (하한) |

| | |
|---|---|
| 보스전 | **적용하지 않는다** — 계단이 잠긴 구간이고 문제를 읽을 시간을 빼앗으면 안 된다 |
| 문제 푸는 중 | 멈춘다 |

최대값을 5.0 → 3.0초로 낮췄다(한 칸에 5초를 주면 기다리는 게임이 된다). 감소 방식도
층당 뺄셈에서 **100층마다 비율(×0.88)** 로 바꿨다 — 뺄셈은 시작값을 낮추면 하한에 닿는
층도 같이 당겨져 초반 난이도가 급변한다.

게이지는 보스 HP 바와 **같은 자리**에 그린다. 둘은 동시에 뜨지 않는다. 남은 30% 부터 붉게
깜빡인다(`prefers-reduced-motion` 이면 색만 바뀐다). 시간은 정답 피드백이 끝난 시점부터 잰다 —
연출 0.25초가 아이의 시간에서 깎이면 2초까지 줄어드는 층에서는 12%다.

### 월드 테마

층 구간에 따라 배경이 바뀐다. **구간은 100층 단위다.** 모델 세트는 4개(숲·성·설산·하늘섬)지만
하늘·안개·조명·계단 색조와 절차적 배경(해/달·별·구름·원경 실루엣·날씨)을 함께 바꿔 6개 구간을
만든다 — 같은 모델로도 "저녁이 됐다"가 전달된다.

| 층 | 테마 | 모델 세트 | 배경 |
|---|---|---|---|
| 0~99 | Word Forest | nature-kit | 맑은 하늘 · 구름 |
| 100~199 | Forest Sunset | nature-kit (따뜻한 색조) | 노을 · 낮게 걸린 해 · 낙엽 |
| 200~299 | Stone Castle | castle-kit | 극적인 구름 · 성탑 실루엣 · 성벽 횃불 |
| 300~399 | Frozen Peak | tower-defense-kit | 빙하 봉우리 · 눈보라 |
| 400~499 | Sky Islands | platformer-pack | 떠 있는 바위 · 폭포 · 황금빛 해 |
| 500~ | Midnight Castle | castle-kit (밤 색조) | 별 260개 · 큰 달 · 횃불 |

계단 모델은 경계에서 딱 바뀌고 하늘·조명만 1.2초에 걸쳐 옮긴다. 그래서 **체크포인트 위쪽에
다음 월드가 미리 보인다.** 계단 색은 콤보 색 × 테마 색조를 곱하므로 같은 GOLD STEP 이
저녁 숲과 밤 성에서 다르게 보인다.

월드2 에셋과 펫은 첫 플레이를 막지 않고 뒤에서 받는다. 아직 안 왔으면 현재 세트로 계속 간다.

#### 환경 오브젝트

계단은 공중에 뜬 구조물이라 지면이 없다. 프롭마다 작은 **섬**을 깔아 떠 있는 것이
의도된 세계관으로 읽히게 한다. 배치는 계단 번호 해시로 결정론적이다 — 회수·재배치 때
나무가 순간이동하면 즉시 눈에 띈다.

| 레이어 | 주기 | 거리 | 크기 | 높이 |
|---|---|---|---|---|
| 근경 | 3칸 | 2.6~4.8 | 0.85~1.35배 | 계단보다 1.1~3.5 아래 |
| **원경** | 7칸 | 5.0~8.0 | **1.7~2.9배** | 계단보다 3~7 아래 |

> **거리는 프러스텀에서 나온 값이다.** 세로 화면은 fov 42°·비 0.49 → 수평 반각 10.6°.
> 22칸 앞(가장 먼 생성 지점)의 화면 반폭이 `(9.4 + 22×0.78) × 0.187 ≈ 5.0` 이다.
> 처음에 근경 3.4~6.6 · 원경 9~15.5 로 뒀더니 **프롭이 한 개도 화면에 들어오지 않았다** —
> 화면의 초록 원뿔은 프롭이 아니라 배경 실루엣이었다. `__ie.propVisibility()` 로
> 프러스텀 안 인스턴스를 세어 확인했다.

원경 레이어를 추가하고 프롭 종류를 세트별로 크게 늘렸다(숲 7 → 20, 성 6 → 19, 설산 5 → 11,
하늘 6 → 13). 숲에는 텐트·모닥불·석상, 성에는 투석기·노포·나무, 설산에는 결정 탑을 넣어
"지나온 곳"으로 읽히게 했다.

**둘 다 draw call 을 거의 늘리지 않는다.** 종류를 늘려도 인스턴스 수가 0 인 종류는 three 가
그리지 않고, 원경은 같은 인스턴스 풀에 담기 때문이다. 실측: 프롭 draw call **6~12개**
(예산 60). 이 전제는 테스트로 고정했다 (`src/world/placement.test.ts`).

### 보스전 · 랜덤 이벤트 (Phase 7)

**보스전이 유일한 출제 창구다.** 10층마다 보스가 등장하면 계단이 잠기고 정답이 보스 HP 를
깎는다. 어려운 단어는 2배 피해, 콤보는 추가 피해(상한 있음).
**보스전에는 계단 타이머가 돌지 않는다.**

보스는 **계단 3칸 위에 서서** 아래를 본다 — 길을 막고 있는 자세여야 관문으로 읽힌다.
좌표는 `stairs.surfaceAt(층 + 3)` 으로 구한다. 플레이어 위치에 오프셋을 더하는 방식은
계단이 올라가며 안쪽으로 뻗는 것을 무시해 보스를 계단 아래에 박아 넣었다(수정함).

| 보스 동작 | 클립 |
|---|---|
| 등장 | `Spawn_Air` — 위에서 떨어져 내려온다 |
| 대기 | `Idle_A` (loop) — 어떤 동작이 끝나도 여기로 돌아온다 |
| 피격(정답) | `Hit_A` / 어려운 단어면 `Hit_B` |
| **공격(오답)** | `Throw` + **플레이어 쪽으로 파고드는 이동** |
| 처치 | `Death_A` |

> KayKit FREE 팩에는 **전용 공격 클립이 없다**(26종 전부 확인). `Throw` 를 휘두르는 동작으로
> 쓰고 돌진 이동을 코드로 만들었다 — 클립만으로는 "때렸다"가 전달되지 않는다.

#### 플레이어 피격 — 보스 공격에 맞춘다

오답이면 보스가 돌진하고, **돌진이 가장 깊이 들어간 프레임에** 플레이어가 맞는다.
플레이어는 `fall`(균형을 잃은 자세) + **보스 반대쪽으로 밀려나는 이동**으로 반응한다.

| | |
|---|---|
| 클립 | `fall` — 플레이어 glb 에도 전용 피격 클립이 없다(32종 확인) |
| 밀려나는 거리 | 0.34 (계단 한 칸 0.78 보다 작게 — 더 밀면 옆 칸으로 떨어진 것처럼 보인다) |
| 방향 | **수평만.** 아래로 밀면 층과 화면이 어긋난다 |
| 시간 | 0.5초 (오답 피드백 1.1초보다 짧다 — 다음 문제가 뜰 때 리액션이 끝나 있어야 한다) |

**타이밍을 `setTimeout` 으로 맞추지 않는다.** 두 가지 이유가 있다:

1. 연출 지연은 **단일 슬롯**(`after`)을 공유한다 — 오답 피드백 타이머와 서로를 취소한다
2. 시간으로 맞추면 프레임이 밀릴 때 타격과 리액션이 어긋난다

그래서 `BossActor.takeImpact()` 가 **돌진 진행도 40% 를 지나는 프레임에 한 번만** 신호를 주고,
update 루프가 그것을 받아 피격을 시작한다. 신호는 소비형이다 — 계속 켜 두면 매 프레임
리액션이 다시 시작된다.

`emote-no` 는 쓰지 않는다. **방향 오선택(판 종료)에 이미 쓰고 있어서** 두 사건이 같은 동작이면
아이가 원인을 구별할 수 없다.

피격은 **계단 상태머신을 건드리지 않는다.** 보스전 중 상태는 `stand` 이고, 여기서 상태가
바뀌면 보스를 잡은 뒤 계단이 열리지 않는다. 자세와 위치만 흔든다.

**보스전 출제 비율이 바뀌었다.** 이전에는 보스전이 취약 단어만 냈다(계단 구간이 신규 단어를
담당했으니까). 문제를 보스전으로 모으자 그 구조는 **신규 단어를 영원히 내지 않는 상태**가 됐다.
그래서 보스전도 비율 자루를 쓴다 — **신규 8 · 복습 5 · 취약 6 · 보너스 1**(취약 비중은
평소 15% 의 두 배). "보스는 약점을 집중 출제한다"는 성격은 유지하면서 어휘가 계속 늘어난다.

실측(100문항 × 4개 실력대, 보스 모드): 신규 31~34 · 복습 34~42 · 취약 23~28 · 보너스 4.

체력은 층과 함께 오른다 — `120 + (보스 번호 − 1) × 25`, 상한 240. 보스가 어려워지는 만큼
낼 문제 수가 늘어난다.

| 층 | 보스 HP | 필요 정답(기본 데미지) |
|---|---|---|
| 10 | 60 | 6문제 |
| 50 | 108 | 11문제 |
| 100+ | 120 (상한) | 12문제 |

체력을 **절반으로 줄였다**(120→60, 상한 240→120). 문제를 보스전에만 모으자 한 보스전이
평균 18문제(약 2분)가 되어 계단을 오르는 시간보다 길어졌다 — 보스는 관문이어야 하고
시험이 되어서는 안 된다.

> **문제를 계단 구간에서 보스전으로 옮긴 결과** (시뮬레이션 200문항 × 40회, 정답률 78%):
> 계단 구간 문제 비율 **45% → 8%**, 도달 층 154 → 140, 보스전 평균 17.9문제.
> 계단을 오르는 동안 문제로 끊기는 일이 거의 없어졌고, 문제는 보스 앞에서 몰아서 나온다.
> 대신 **한 보스전이 길다**(평균 18문제). 짧게 하려면 `BOSS_HP_MAX` 를 내리거나
> `BOSS_EVERY` 를 15로 올린다(15층으로 하면 도달 층 153, 계단 구간 문제 11%).

| 이벤트 | 규칙 변화 |
|---|---|
| Treasure | 즉시 골드 |
| Double XP | 다음 3문제 보상 2배 |
| Golden Word | 이 문제 보상 3배 |
| Speed | 5초 안에 맞히면 2배 — **넘겨도 벌은 없다** |
| Mystery | 조금 어려운 문제 + 보상 2배 |
| Escape | 시간 안에 계단 구간을 올라야 콤보를 지킨다 |

**어떤 이벤트도 HP 를 깎지 않는다.** HP 는 영어 오답 전용이라는 규칙을 이벤트가 깨면
아이는 왜 죽었는지 모른다.

### 로비 — 문제 난이도 선택 · 상점

#### 문제 난이도 (레벨 선택)

로비에서 학년 구간을 고른다. **레벨 숫자가 아니라 학년으로 보여 준다** — 아이에게 "레벨 7"은
아무 의미가 없고, PRD 3장은 아이 화면에 등급을 노출하지 않는다(추천 레벨은 부모 화면에만).

| 선택 | 레벨 | 학년 |
|---|---|---|
| **자동** (기본) | 제한 없음 | adaptive(theta)가 정한다 |
| 초3~4 | 1~3 | 초3 · 초4 |
| 초5~6 | 4~5 | 초5 · 초6 |
| 중1 | 6~7 | 중1 |
| 중2~3 | 8~10 | 중2 · 중3 |

선택은 adaptive 를 **대체하지 않고 그 위에 씌우는 제한**이다. 자동이 정답률 75~85% 를 맞추는
장치이므로 기본값으로 두고, 선택은 "우리 아이는 초등인데 중등 단어가 나온다" 를 부모가 직접
막는 용도다. 복습·취약 큐의 단어도 같은 제한을 받는다 — 그러지 않으면 선택의 의미가 없다.

**구간이 비면 전체로 되돌아간다.** 선택은 취향이고 게임이 멈추는 것보다 약하다.
판 도중에는 바뀌지 않는다(로비에서만).

#### 상점 — 무기 22종 · 캐릭터 6종

골드로 산다. **화폐는 골드다(점수가 아니다)** — 점수는 판마다 0 으로 초기화되므로 상점
화폐가 될 수 없고, 판을 넘어 누적되는 것은 골드다(정답 3 · 체크포인트 · 크리스탈 ·
보스 처치 · Treasure · 일일 미션).

| 카테고리 | 가격대 | 종류 |
|---|---|---|
| 무기 | 1,000 ~ 5,000 | 검 5 · 도끼 3 · 망치 3 · 단검 2 · 너클 2 · 지팡이 2 · 활 2 · 창 · 할버드 · 마법봉 |
| 캐릭터 | 5,000 ~ 10,000 | 야만전사 · 궁수 · 도적 · 두건 도적 · 기사 · 마법사 |

목록은 **가격 오름차순**이다 — 아이가 위에서부터 훑으면 "지금 살 수 있는 것"을 먼저 만난다.
살 수 없는 것은 "450 더 모으기"로 남은 양을 적는다.

가격은 **시뮬레이션 위에서 정했다.** 실제 골드 함수로 하루 5판을 돌린 결과 보통 실력
약 1,400골드 / 익숙해지면 4,600골드다. 그래서 무기는 "첫날~며칠", 캐릭터는 "몇 주"의 목표가 된다.

##### 무기 — 보스전 정답에 휘두른다

산 무기는 로비의 무기 목록에 담기고 **기본은 "없음"** 이다. 장착하면 보스전에서 정답을
맞힐 때 공격 동작이 나온다. 화살(`arrow_A`·`arrow_B`)은 상점 항목이 아니라 **활에 종속**되어
활을 들면 함께 붙는다. 방패는 공격 모션에 쓸 수 없어 제외했다.

무기를 붙이는 지점은 리그마다 다르다 — 실측한 결과다:

| 리그 | 본 | 결과 |
|---|---|---|
| KayKit Rig_Medium (상점 캐릭터) | `handslot.r` | 무기 슬롯이 있다 — 제대로 쥔다 |
| Kenney mini-characters (기본 캐릭터) | **손 본이 없다** (본 7개) | 팔 끝(`arm-right`)에 붙인다 |

기본 캐릭터는 손이 없는 블록 형태다(Kenney 공식 샘플도 물건을 팔에 붙인다). 그래서
"제대로 쥔 모습"을 보려면 상점 캐릭터를 사야 한다 — **제약이지 버그가 아니다.**

##### 캐릭터 — 클립 이름이 다르다

산 캐릭터는 로비의 캐릭터 목록에 ⭐ 표시로 섞여 들어간다(레벨 해금 캐릭터와 한 목록이다 —
아이에게는 둘 다 "내 캐릭터"이고 잠금 규칙만 다르다).

**KayKit Adventurers 는 애니메이션이 0개다.** 보스와 같은 `Rig_Medium` 이라 `boss-anims` 의
26종을 빌려 쓴다(스파이크 A 에서 검증한 구조). 그런데 클립 이름이 기본 캐릭터와 완전히 다르다:

| 역할 | Kenney | Rig_Medium |
|---|---|---|
| 대기 | `idle` | `Idle_A` |
| 점프 | `jump` | `Jump_Full_Short` |
| 피격 | `fall` | `Hit_A` |
| 방향 오선택(종료) | `emote-no` | `Death_A` |
| 공격 | `attack-melee-right` | `Throw` |

그래서 게임 코드는 **이름이 아니라 역할**로 부른다(`Actor.playRole`). 이름을 박아 두면
캐릭터를 사는 순간 애니메이션이 전부 죽는다.

### 성장 (Phase 6)### 성장 (Phase 6)

경험치는 **영어 문제를 맞혀야만** 오른다. 난이도와 콤보를 반영하고, 복습 정답은 절반만 준다 —
같은 단어를 반복해 경험치를 벌 수 없다. 그래서 수집·성장은 학습량의 다른 이름이다.

능력치 4종은 RPG 스탯이 아니라 **학습 성과를 게임 언어로 번역한 것**이고, 누적 기록에서
파생하므로 따로 저장하지 않는다.

| 능력치 | 근거 |
|---|---|
| STR | 최고 연속 정답 |
| SPEED | 3초 안에 맞힌 횟수 |
| INT | 난이도 0.5 이상 단어 정답 횟수 |
| MEMORY | 완전히 익힌(Mastered) 단어 수 |

- **캐릭터 6종 · 펫 4종**을 레벨로 해금한다 (Lv.1/3/4/6/8/10/12/15/20)
- **Daily Mission 3종** — 날짜를 시드로 뽑으므로 새로고침해서 쉬운 미션을 다시 뽑을 수 없다.
  레벨 조건이 있어 아직 10층도 못 간 아이에게 "40층 도달"을 내지 않는다
- **Streak + Shield** — 7일마다 방패 1개(최대 2). 하루 빠져도 기록이 지켜진다
- **이어하기** — 창을 닫아도 층·HP·콤보·점수가 복원된다
- **부모용 화면** — 13개 지표 + 취약 단어. 추천 레벨은 여기에만 있다(아이에게 등급을 보여 주지 않는다).
  전부 이 기기에서 계산하고 서버로 보내지 않는다

저장 스키마는 v2이고 **v1 → v2 마이그레이션이 학습 기록을 보존**한다(테스트로 고정).

### 학습 엔진

무엇을 낼지는 `learning/engine.ts` 가 정한다. 게임 규칙(HP·콤보·계단)과 분리되어 있고,
three·DOM 을 import 하지 않는다 — Node 에서 그대로 돌아 시뮬레이션·테스트가 가능하다.

| 규칙 | 구현 |
|---|---|
| 출제 비율 신규 50 / 복습 30 / 취약 15 / 보너스 5 | 20문항 자루(bag)를 섞어 뽑아 오차 0 |
| 틀린 단어 재출제 | 30초 → 5분 → **다음 판**(세션 큐에서 내려간다) |
| 세션 간 복습 | 3분 → 1일 → 3일 → 7일 → 21일 (SM-2 축약) |
| Mastery 100% | EN→KO ✓ · KO→EN ✓ · **하루 뒤 재정답** ✓ — 한 번 맞힌 것으로는 안 된다 |
| 개인별 난이도 | IRT 1PL theta 추정, 목표 정답률 75~85% 밴드, 한 문항당 변화 상한 |
| 파도형 난이도 | 어려운 문제를 연속으로 내지 않는다 |

학습 상태는 `localStorage` 에 버전드 스키마로 저장한다(계정·서버 없음).

### 단어 DB

`tools/seed/*.tsv` 를 편집하고 `npm run words` 를 돌린다. 빌드가 검증 10종을 통과하지 못하면
산출물을 쓰지 않는다. 현재 **Level 1~10 1,000단어** — 초3 91 / 초4 195 / 초5 85 / 초6 84 /
중1 220 / 중2 220 / 중3 105. 명사 535 · 동사 227 · 형용사 192 · 부사 등 46.

가장 중요한 검사는 **뜻 충돌**이다. `eye`(눈)와 `snow`(눈)처럼 한국어 표기가 같으면
KO→EN 문제의 정답이 둘이 된다 — 빌드가 이를 막고, 표기를 `눈(신체)`/`눈(날씨)` 로 구분하게 한다.
자세한 규칙은 [`tools/seed/README.md`](tools/seed/README.md).

**게임은 10개 레벨을 전부 로드한다**(`main.ts` 의 `LEVELS`). 오답 후보(`distractorPool`)가
1,000개 전체에서 계산되므로 일부만 로드하면 후보가 해결되지 않는다 — L6~10 을 추가한 직후
`village` 의 후보 12개가 전부 L6 여서 4지선다를 만들 수 없었다. 전 레벨을 받아도 gzip 82KB 다.
아이가 만나는 난이도는 로드 범위가 아니라 adaptive(theta)가 정한다.

### 개발용 URL 파라미터

실기기 측정용이다. 특히 성능은 기기에서 두 설정을 번갈아 재야 판단할 수 있다.

| 파라미터 | 뜻 |
|---|---|
| `?seed=1234` | 계단 방향 고정 (같은 판 재현) |
| `?spec=low` \| `high` | 렌더 프로파일 강제 (저사양: DPR 1.25 · AA off · 프롭 절반) |
| `?side=front` \| `double` | 머티리얼 side 강제 — **doubleSided 의 fill-rate 비용 측정용** |
| `?autodir=1` | 방향 자동 보정 (접근성 옵션 확인) |
| `?floor=350` | 시작 층 강제 (뒤쪽 월드·배경 확인용) |

우상단 HUD에 `fps · draw call · 삼각형 · 픽셀 수 · 프로파일`이 상시 표시된다.

`window.__ie` 로 상태를 읽고 조작할 수 있다 — `phase` `floor` `hp` `combo` `score`
`quiz` `stats` `climbState` `stairTimer` `failReason`, 그리고
`answerCorrect()` · `answerWrong()` · `tap(-1|1)` · `climbSegment(칸수)`.
(`stepsLeft` 는 계단 구간 개념이 없어져 사라졌다)

검증용 훅 세 개가 더 있다. 전부 실제 버그를 잡아서 남겼다:

| 훅 | 무엇을 잡았나 |
|---|---|
| `canClimb` | 보스 등장 연출 0.9초 동안 계단이 열려 있어 **보스를 통과해 올라갔다** |
| `clips` | 재생 중인 클립(플레이어·보스). 애니메이션이 죽는 사고가 두 번 있었다 |
| `propVisibility()` | 프러스텀 안 프롭 수. **배치는 됐지만 화면에 0개**였다 |

> `tap()` 은 실제 입력과 **같은 게이트**(`canClimb()`)를 지난다. 처음에는 `climb.input()` 을
> 직접 불러서, 잠금을 넣은 뒤에도 검증이 계속 통과했다 —
> **검증 도구가 실제보다 관대하면 검증은 거짓말이 된다.**
**보기 클릭·입력과 같은 경로를 타므로** "테스트만 통과하는 코드"가 되지 않는다.

> 조용히 멈춘다. 파이프라인이 이 경우를 에러로 막는다.
