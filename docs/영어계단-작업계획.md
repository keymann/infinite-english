## 1. 개발 · 배포 환경 (기준 프로젝트와 동일)

기준 프로젝트의 설정을 그대로 이식한다. 달라지는 부분만 아래에 명시한다.

| 항목 | 기준 프로젝트 | 영어계단 |
|---|---|---|
| 언어·빌드 | TypeScript strict + Vite 7 | 동일 |
| 배포 | Cloudflare **Workers Static Assets** (`wrangler.jsonc`, `main` = `src/worker/index.ts`, `assets.directory=./dist`) | 동일. `name: "infinite-english"` |
| 404 처리 | `not_found_handling: "404-page"` (멀티페이지이므로 SPA 모드 금지) | 동일 — `index.html` + `quality.html` 멀티페이지 |
| 랭킹 DB | D1, 단 `d1_databases`는 **주석 처리**로 시작 (없는 database_id로 배포하면 조용히 깨짐) | 동일 패턴. MVP는 로컬 저장만, 기록 공유는 Phase 8 |
| PWA | `vite-plugin-pwa` (autoUpdate, 오프라인 플레이) | 동일. 단 **glb 는 프리캐시에서 제외**하고 `/models/*.glb` 를 CacheFirst 런타임 캐시로 둔다 (4.2절) |
| 캐시 정책 | `public/_headers` — `/assets/*` immutable, html no-cache | 동일 + `/models/*` immutable (파일명에 해시 부여) |
| dev 서버 | `host: true`, 5173 (실기기 확인용) | 동일 |
| npm scripts | `dev` `build`(tsc --noEmit && vite build) `preview` `typecheck` `deploy` `sim` | 동일 + **`assets`**(3D 에셋 최적화) |
| 문서 | `docs/*.md` + README에 링크 | 동일 |

**추가 의존성**

```
three                          # 렌더러 (설치본 0.185)
@gltf-transform/core           # (dev) 에셋 파이프라인 — 병합·프루닝·머티리얼 dedupe
@gltf-transform/functions      #        mergeDocuments / dedup / prune
@gltf-transform/extensions     #        KHR_texture_transform 등 원본 확장 보존
vitest                         # (dev) 학습 엔진 로직 회귀 테스트 ※ 기준 프로젝트에는 없으나 추가 권장
```

> `typescript` `vite` 는 기준 프로젝트와 같은 메이저에 맞춘다(5.9 / 7.x). 최신 설치본은
> TypeScript 7 · Vite 8 로 올라가지만, "환경 동일"이 이 프로젝트의 전제이므로 고정한다.

> 기준 프로젝트는 테스트 스크립트가 없다. 여기서는 Mastery·Spaced Repetition·Adaptive 난이도가
> **눈으로 검증 불가능한 로직**(며칠 뒤의 재출제 시점 등)이라 단위 테스트 없이는 회귀를 못 잡는다.
> 렌더링·연출은 테스트하지 않고 로직 3개 모듈만 대상으로 한다.

**React를 쓰지 않는다** — 기준 프로젝트와 같은 이유. 60fps three.js 루프가 렌더의 주체이고,
퀴즈 패널·오버레이는 상태 전이 시점에만 갱신되는 정적 구조다.

## 2. 3D 스택 선정

| 후보 | 판단 |
|---|---|
| **three.js** ✅ | glTF 로더·SkinnedMesh·AnimationMixer·InstancedMesh가 표준 탑재. Kenney/KayKit 에셋이 전부 glTF이므로 변환 없이 그대로 쓴다. gzip 후 약 160KB |
| Babylon.js | 기능은 충분하지만 번들이 2~3배. 물리·에디터 등 이 게임에 필요 없는 기능 비중이 큼 |
| 순수 WebGL | 스키닝 애니메이션을 직접 구현해야 함. 캐릭터 애니 32종을 손으로 다룰 이유가 없다 |
| React Three Fiber | React를 끌어들이는 비용 대비 이득 없음 (1장 참고) |

**렌더 방침** — 저사양 태블릿 30fps 이상이 하한선이다.

- 포스트프로세싱 **미사용** (모바일 fill-rate 즉사 요인)
- 조명 = `HemisphereLight` + `DirectionalLight` 1개. 실시간 그림자는 **blob 그림자 데칼**로 대체하고,
  `shadowMap`은 고사양 옵션에서만 512px 단일 캐스터로 켠다
- 계단·프롭은 `InstancedMesh`. 스키닝은 플레이어 1체 + 펫 1체 + 보스 1체까지만
- DPR 상한 2 (저사양 모드 1.25), `antialias`는 DPR 1.5 미만에서만 on
- 카메라는 **원근 투영 고정각** (수직 회전 없음) — 계단 지그재그의 좌/우 판단이 항상 같은 화면 방향이어야 한다

**성능 예산 (한 프레임)**

| 지표 | 목표 |
|---|---|
| draw call | 60 이하 |
| 삼각형 | 150k 이하 |
| 스키닝 캐릭터 | 3체 이하 |
| 초기 다운로드(모델) | **3MB 이하** (월드 추가분은 lazy, 월드당 1MB 이하) |
| fps | 폰·아이패드 60 / 보급형 안드로이드 태블릿 30 |

## 3. 게임 설계 — 3D 무한 계단

### 3.1 핵심 조작 (원작형 방향 판단 채택)

문제 풀이(사고)와 방향 탭(반사)을 **시간적으로 분리**한다. 둘을 동시에 요구하면 인지 부하가 겹쳐
어느 쪽도 제대로 안 된다.

```
문제 출제 → 보기 4개 중 선택
   ↓ 정답
계단 구간 N칸 생성 (콤보에 따라 N 증가)
   ↓
좌/우 탭으로 N칸을 연달아 오른다  ← 원작 무한의 계단 구간
   ↓
구간 통과 → EXP/GOLD → 다음 문제
```

**콤보가 곧 계단 길이다.** 정답 보상이 숫자가 아니라 게임 액션으로 나타난다 (PRD 35장 3항).

| 콤보 | 구간 길이 | 계단 연출 |
|---|---|---|
| x1~2 | 1칸 | 일반 |
| x3~4 | 2칸 | 일반 |
| x5~9 | 3칸 | GOLD STEP |
| x10~19 | 4칸 | FIRE STEP |
| x20+ | 4칸 + 시간 보너스 | LIGHTNING STEP |

### 3.2 방향 실수 페널티 (설계 핵심)

| 사건 | 결과 |
|---|---|
| 영어 오답 | **HP -1**, 콤보 리셋, 오답 큐 등록 |
| 방향 실수 | 캐릭터 휘청(0.4초 정지) + 콤보 **1단계 하락**. HP 불변 |
| 같은 구간 3회 실수 | 구간 자동 통과 (진행을 막지 않는다) |
| 구간 제한시간 초과 | 콤보 리셋만. HP 불변 |

> HP를 방향 실수와 공유하면 "영어를 틀려서 실패했다"는 인과가 흐려지고, PRD 35장 4항
> (오답을 학습 기회로)이 무너진다. 조작은 **보상 배율**을, 영어는 **생존**을 담당한다.

**접근성**: 설정에 `방향 자동 보정` 스위치를 둔다(켜면 탭 한 번에 알아서 오른다).
저학년·소근육 발달 차이를 조작 난이도로 걸러내면 안 된다.

### 3.3 계단 생성

- 계단 i+1 = 계단 i + `(±X, +Y)` — 좌/우 지그재그, 높이 일정
- 방향 시드는 `core/rng.ts`(시드 난수)로 결정 → 리플레이·시뮬레이터 재현 가능
- 화면 밖(아래) 계단은 **풀로 회수**해 위쪽에 재배치. 상시 유지 계단 수 ~24칸
- 10·20·30·50층 체크포인트에서 계단 재질·프롭 세트 교체 → "올라왔다"는 감각을 시각으로 준다
- 카메라는 Y를 스프링 추적, X는 캐릭터 X를 감쇠 추적 (지그재그가 화면을 흔들지 않게)

### 4.1 에셋 파이프라인 (구현 완료 — Phase 0)

원본 kit 폴더(총 168MB)를 `public/`에 넣지 않는다. 화이트리스트에 적힌 모델만 bundle 단위로
병합해 `public/models/`로 낸다.

```
npm run assets     # tools/optimize-assets.mjs + tools/asset-manifest.json
```

1. 화이트리스트(`asset-manifest.json`)의 glb만 수집 — 없는 이름은 에러로 막는다
2. bundle 단위 **하나의 glb로 병합**. 각 모델은 `<모델명>` 래퍼 노드로 감싸 이름으로 꺼낸다
3. `mergeDocuments` → 버퍼 통합 → `dedup()` → `prune({ keepLeaves: true })`
4. 산출: `public/models/*.glb` + `manifest.json`(bundle·노드 목록·용량). 산출물은 커밋한다

> **병합의 실제 이득은 바이트가 아니라 요청 수와 머티리얼 공유다.** Kenney glb는 아틀라스를
> 내장하지 않고 `Textures/colormap.png`를 **외부 URI로 참조**한다(kit당 7~12KB 1장). 따라서
> 개별 로드해도 텍스처는 브라우저가 한 번만 받는다. 병합으로 얻는 것은 ① 45요청 → 6요청,
> ② `dedup()`이 머티리얼을 하나로 합쳐 셰이더 프로그램·draw call이 줄어드는 것이다
> (food 25모델 → 머티리얼 1종, 실측).

**`prune()`의 기본값을 쓰면 안 된다** — 본(bone)은 메시가 없는 리프 노드다. 기본
`keepLeaves: false`로 돌리면 애니메이션 타겟인 본이 지워지고, 클립은 경고만 남기며 조용히
아무것도 움직이지 않는다.

#### 스킨드 캐릭터는 bundle 하나에 하나만 (파이프라인이 에러로 막는다)

같은 리그를 쓰는 캐릭터 2개를 한 glb에 합치면 본 이름(`hips`, `hand.r` …)이 중복되고,
three의 GLTFLoader가 뒤에 오는 쪽에 `_1`을 붙여 유일화한다. 그러면 공유 클립의 트랙 이름과
본 이름이 어긋나 **경고만 남기고 애니메이션이 멈춘다.** 프롭(스킨 없음)은 이름이 겹쳐도
애니메이션에 영향이 없으므로 얼마든 병합해도 된다.

같은 이유로 **애니메이션 전용 bundle은 리그를 통합한다** — 애니메이션 파일 2개를 병합하면
리그가 2벌 들어오므로, 첫 리그를 정본으로 두고 모든 채널을 이름으로 재바인딩한 뒤 중복을 지운다
(`mergeRigs()`, 채널 754개 재바인딩 실측).

#### three의 노드 이름 정규화

three는 노드 이름에서 `.` `:` `/` `[` `]`를 제거한다(`PropertyBinding.sanitizeNodeName`).
원본의 `hand.r`은 씬에서 `handr`이 된다 — **원본 이름으로 `getObjectByName`하면 못 찾는다.**
런타임 코드는 조회 시 반드시 같은 정규화를 적용할 것.

### 4.2 스파이크 결과 (실측, 2026-08-11)

검증 페이지 `spikes/spike.html` (개발용, 배포 대상 아님 — `vite.config.ts`의 build input에 없다).

## 7. 단어 DB 구축 (교육과정 기준 자체 구축)

**규모**: MVP는 Level 1~5 = 초3~초6 핵심 **약 1,000단어**. 최종 L1~10 약 3,000단어.

### 공정

| 단계 | 내용 | 산출 |
|---|---|---|
| 1. 시드 | 교육부 「초·중학교 영어과 교육과정」 별표 기본어휘 + 초등 교과서 공통 어휘를 CSV로 정리 | `tools/seed/words.csv` (word, 학년, 품사) |
| 2. 레벨 매핑 | 학년 → Level 1~10, 월드 배정 (PRD 3·17장) | `curriculum.ts` |
| 3. 초안 생성 | LLM 배치로 `meaning` `meaningAlt` `예문` `예문번역` `tags` `유의어/반의어` 생성 | 초안 JSON |
| 4. 자동 검증 | 아래 검증 규칙 전수 실행. 실패 항목은 재생성 또는 검수 큐 | 검증 리포트 |
| 5. 사람 검수 | 자동검증 실패 **전수** + 통과분 레벨별 **20% 샘플** | 확정 JSON |
| 6. 빌드 | 스키마 검증 → `distractorPool` 프리컴퓨트 → `data/words/level-N.json` | 최종 산출 |

### 자동 검증 규칙 (`tools/build-words.ts`)

| 검사 | 실패 예 |
|---|---|
| **뜻 충돌** — 같은 레벨대에 뜻이 동일/유사한 단어 쌍 | `ancient`(고대의)와 `old`(옛날의)가 서로의 오답이 되면 정답을 골라도 오답 처리된다 |
| 예문에 표제어 포함 | `ancient` 예문에 ancient가 없음 |
| 예문 난이도 | 예문에 표제어보다 높은 레벨 단어가 2개 이상 |
| 예문 길이 | 초등 8단어 / 중등 12단어 초과 |
| 품사 일치 | 품사가 adjective인데 뜻이 "고대"(명사형) |
| 한국어 뜻 형식 | 형용사는 "~한/~의", 동사는 "~다"로 끝나는지 |
| 금칙 | 폭력·성·질병 등 아동 부적절 어휘 |
| `clozeIndex` 유효성 | 빈칸 위치가 표제어 토큰을 가리키는지 |

> **가장 중요한 검사는 뜻 충돌이다.** 기준 프로젝트에서도 같은 계열의 버그(오답이 정답과 같은 값)로
> 전수 검사 400개 중 200개가 걸린 전례가 있다. 생성기 여러 곳에 흩어 막으면 반드시 하나를 빠뜨리므로,
> **빌드 시점 한 곳에서** 걸러 `meaningAlt`로 기록하고 런타임 오답 후보에서 제외한다.

**음성(TTS)**: MVP는 Web Speech API(무료). 지원이 불균등하므로 없으면 조용히 생략한다.
V2에서 사전 생성 오디오로 교체 (단어 1,000개 × 20KB ≈ 20MB → lazy·레벨별 분할 필수).

## 8. 학습 엔진 사양

### 8.1 출제 비율 (PRD 8장)

신규 50 / 복습 30 / 취약 15 / 보너스 5. **파도형 난이도 곡선**(PRD 24장)을 20문항 템플릿으로 고정하고,
개인 `theta`를 오프셋으로 얹는다. 같은 단어 연속 출제 금지(직전 3문항 제외 창).

### 8.2 Adaptive (IRT 1PL 간이)

```
p(정답) = 1 / (1 + exp(-(theta - difficulty)))
정답: theta += K * (1 - p)     오답: theta -= K * p
K = 0.35 (calibration 중) → 0.12 (이후)
|Δtheta| ≤ 0.15 / 문항   ← 급변 금지 (PRD 7장)
```

출제는 **목표 정답률 75~80% 밴드**에서 고른다. 너무 쉬우면 지루하고 60% 미만이면 이탈한다.
Calibration은 쉬움-보통-어려움을 섞은 10문항으로 초기 `theta`·`confidence` 추정.

### 8.3 Spaced Repetition

세션 내 큐와 세션 간 큐를 **분리**한다 (하나로 합치면 30초 후 재출제와 3일 후 재출제가 같은 자료구조에서 싸운다).

| 큐 | 간격 |
|---|---|
| 세션 내 (초) | 오답 → 30초 → 5분 |
| 세션 간 (일) | 다음 게임 → 1일 → 3일 → 7일 → 21일 (SM-2 ease factor 조정) |

### 8.4 Mastery (PRD 9장)

5단계. 100% 도달 조건은 정답 횟수가 아니라 **유형 게이트**다.

```
EN→KO 정답 ✓   KO→EN 정답 ✓   문맥/문장 정답 ✓   24시간 이후 재출제 정답 ✓
→ WORD MASTER
```

#### 단위 테스트가 잡은 버그 (기록)

세 개 모두 **화면으로는 발견할 수 없는** 종류였다.

| 버그 | 증상 | 원인 |
|---|---|---|
| **적응 난이도 부호 오류** | 목표 난이도가 실력보다 **위**로 잡혔다 (정답률 기대치 20%) | `d = theta + ln(p/(1-p))` 를 써야 할 곳에 부호를 뒤집어 씀 |
| SR 첫 간격이 1일 | 첫 판에서 복습 후보가 전부 미래 시점이 되어 **복습 30% 를 채울 수 없었다** | 정답 간격 단계를 `[0일, 1일, …]` 로 시작 → `[3분, 1일, …]` 로 수정 |
| 난이도 보정 단위 혼용 | 파도 보정 0.14 가 unit 축이라 **1.26레벨 점프**가 됐다. 하한 실력 학생의 정답 확률이 70%→27% | 난이도 계산을 전부 레벨 축으로 통일 (`targetLevelRange`) |

여기에 데이터 쪽 문제 하나가 더 있었다. `build-words.ts` 가 난이도에 **하한 0.05** 를 걸어
가장 쉬운 단어가 레벨 1.45 였다 — 이제 시작하는 초3 학생의 정답률 상한이 63% 로 묶였다.
Level 1 고빈도 단어(cat·dog·apple)는 커리큘럼의 바닥이므로 난이도 0 이 맞다. 하한을 없앴다.

그리고 넓은 화면에서 보기 버튼이 끝까지 늘어나 손가락이 닿지 않는 곳에 글자가 놓였다
(폭 상한 560px + 가운데 정렬). **태블릿 가로 2단 레이아웃(3.4절)은 아직 남았다.**

## 10. 목표 지표 (Phase 9 수렴 목표)

| 지표 | 목표 | 이유 |
|---|---|---|
| 한 판 평균 정답률 | **75~85%** | 60% 미만은 이탈, 90% 초과는 학습이 안 일어남 |
| 한 판 시간 | 3~5분 | PRD 23장 |
| 한 판 출제 문항 | 18~25 | 계단 상승 템포 |
| 첫 성공 경험 도달 | **30초 이내** | PRD 23장 |
| 오답 단어 재학습 성공률 | 같은 세션 내 70% 이상 | 오답 복습 시스템이 실제로 작동하는지 |
| Mastery 전환율 | 노출 단어 중 주당 15% 이상 | 아는 단어만 반복하고 있지 않은지 |
| 방향 실수로 인한 판 종료 | **0%** (설계상 불가) | 3.2절 |
| fps | 저사양 태블릿 30 / 그 외 60 | 2장 |
| 초기 로딩 | 3G 환경 5초 이내 첫 플레이 | 모델 3MB 예산 |

시뮬레이터는 기준 프로젝트와 같은 방식으로 **가상 학생 봇**을 돌린다. 다만 측정 대상이
생존 시간이 아니라 **학습 지표**(Mastery 증가율, 오답 재학습 성공률, 난이도 수렴 속도)다.
