# 단어 시드 데이터

## 왜 TSV 인가

CSV 가 아니라 **탭 구분(TSV)** 이다. 한국어 뜻과 예문 번역에 쉼표가 자주 들어가고
(`"이것은 고대의 성이다, 아주 오래된."`), CSV 로 두면 따옴표 이스케이프가 데이터 오류의
주된 원인이 된다. 탭은 본문에 등장하지 않는다.

## 컬럼

| 컬럼 | 설명 |
|---|---|
| `word` | 표제어 (숙어도 이 컬럼에 그대로 — `look after`) |
| `level` | 1~10 (게임 내부 난이도) |
| `grade` | `elementary_3` … `middle_3` |
| `pos` | `noun` `verb` `adjective` `adverb` `preposition` `verb_phrase` |
| `meaning` | 대표 뜻 하나. **문제의 정답으로 그대로 쓰인다** |
| `meaningAlt` | 정답으로도 인정할 다른 뜻 (`\|` 구분). 오답 후보에서 이 뜻을 가진 단어를 제외하는 근거 |
| `synonyms` | 동의어 표제어 (`\|` 구분). **뜻이 겹치는 단어는 반드시 여기 선언해야 빌드가 통과한다** |
| `tags` | 의미 범주 (`animal` `food` `emotion` …). 좋은 오답을 뽑는 1순위 기준 |
| `freq` | `high` `mid` `low` — 편집자 판단의 거친 3단계. **코퍼스 실측값이 아니다** |
| `example` | 예문. 표제어가 반드시 들어가야 한다(빈칸 문제로 재사용) |
| `exampleKo` | 예문 번역 |
| `image` | `food.glb` 의 노드 이름 (TYPE_C 그림 문제용). 없으면 빈칸 |

## 뜻 충돌 규칙 (가장 중요)

`big`(큰)과 `large`(큰)처럼 뜻이 겹치는 단어가 서로의 오답 보기로 들어가면
**정답을 골랐는데 오답으로 채점된다.** 그래서 빌드 단계에서 정규화한 뜻이 겹치는 쌍을
전수 검사하고, `synonyms` 에 서로를 선언하지 않았으면 **에러로 막는다**.
선언된 쌍은 오답 후보에서 상호 제외한다.

## 공정

```
tools/seed/*.tsv  →  npm run words  →  src/data/words/level-N.json (+ 검증 리포트)
```

1차 배치는 Level 1~2(초3~초4). 이후 배치도 같은 스크립트로 누적한다 —
파일을 추가하면 자동으로 읽는다. 현재 **Level 1~10 · 1,000개**로 목표 분량을 채웠다.

## 단어를 추가할 때 주의할 것

`distractorPool` 은 **DB 전체에서** 계산된다. 그래서 새 레벨을 넣으면 기존 단어의 오답 후보가
밀려난다 — L6~10 을 추가했을 때 `village`(tags=place 하나뿐)의 상위 12개가 전부 L6 장소 단어로
채워졌고, L1~5 만 로드하던 게임에서 4지선다를 만들 수 없었다.

그래서 **태그를 두 개 이상** 달아 두는 편이 안전하다. 태그가 하나면 같은 태그의 새 단어가
후보를 독점한다. 빌드가 `범주가 얇음(4개 미만)` 으로 알려 주니 그 목록을 비워 두는 것을 권한다.
